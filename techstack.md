# Tech stack

Decisions for the Kakar Adi Kali Sahasranama site. Each choice is stated with the
constraint that forced it, so a later reviewer can overturn it knowingly.

---

## 1. The stack

| Layer | Choice | Why |
|---|---|---|
| Generator | **Astro 6.4.8**, `output: 'static'` | Ships zero JS by default; every name is real HTML at build time. The reference site already proves this shape at 1,000+ pages. |
| Styling | **One hand-written CSS file**, `src/styles/pothi.css` | The design is 300 lines of tokens and components. Tailwind would add a second vocabulary for no gain. |
| JS | Vanilla, `<script>` islands only | Theme toggle, search filter, mobile menu. No framework, no hydration. |
| Content | **Astro content collection** over `output_names/*.md` at build | Markdown stays the source of truth and stays out of the published output. |
| Search | Custom normalized index, built at build time | A diacritic-insensitive match is a hard requirement; no off-the-shelf static search does it well. §4. |
| Fonts | Self-hosted WOFF2, subset | Reference used Google Fonts; self-hosting removes a third-party round trip and the FOIT. |
| Deploy | **Cloudflare Pages, Direct Upload** | Per `AGENTS.md` §6. Git never sits in the deploy path. |
| Node | 22 LTS | Astro 6 baseline. |

**Rejected:** Next/Nuxt (client JS for a text site), Hugo (no content-collection
ergonomics for 1,000 structured entries), a prebuilt single-page bundle (one
crawlable URL for 1,000 names — the exact failure this project must avoid).

## 2. Routes

```
/                          reader — frontispiece, title, counts, opening eleven
/names/                    hub — 10 ranges, contents list
/names/1-100/ … /names/901-1000/     range index, 100 rows each
/names/krim/ …             one page per unique name (965)
/about/  /sources/  /privacy/
/404.html
/sitemap.xml  /robots.txt  /llms.txt
/search-index.json         generated, immutable-cached
```

**Why name pages, not position pages.** The text has 1,000 positions but 965
unique names — `kali` appears three times, ~34 others twice. One page per
position would create 35 near-duplicate pages competing with each other. So a
name page is keyed by slug and lists every position where it occurs
(`page.positions: [2]`, `page.positions: [1, 44, 712]`), and the folio shows the
first position. Ranges preserve reading order.

Slug = `slugify(title)`, ASCII, lowercase, collision-checked at build.

## 3. Data pipeline

`output_names/NNNN-slug.md` → parsed once at build into:

```ts
type Name = {
  position: number;        // 1…1000
  title: string;           // "Krim"
  devanagari: string;      // "क्रीं"
  iast: string;            // "Krīṃ"
  source: string;          // "KRIM" — original transliteration
  alternates: string[];    // ["Kreem", "Kriim", "Kreen"]
  meaning: string;         // one line
  intro: string;           // opening paragraph (HTML)
  sections: { title: string; body: string }[];  // elaboration
};
```

Parsing lives in `src/lib/names.ts` and is the only code that knows the Markdown
shape. It fails the build — loudly — if an entry is missing `Devanagari:`,
`IAST:`, `Meaning:`, or a `##` title.

`output_names/` is **not** copied to `dist/`. Only rendered HTML ships. The build
asserts that `dist/` contains no `.md`, no `.txt`, no `private/` (see §8).

## 4. Search

Requirement: typing `kali`, `kālī`, `काली`, or `KAALEE` must all find the same
name. That kills naive substring search and it kills Pagefind's tokenizer, which
does not fold IAST diacritics.

**Approach — a prebuilt folded index, ~60 KB brotli, loaded on first focus.**

```js
const fold = s =>
  s.normalize('NFD').replace(/[\u0300-\u036f]/g, '').toLowerCase();
```

NFD decomposition turns `ā ī ṛ ṃ ś ṣ ṇ ñ ṅ` into base letter + combining mark, so
one regex strips them all. Devanagari passes through untouched and is matched
literally.

Each row indexes, folded and space-joined:
`title · devanagari · iast · source · alternates · meaning`.

```json
{"p":1,"t":"Krim","d":"क्रीं","i":"Krīṃ","s":"KRIM","a":["Kreem","Kriim","Kreen"],
 "m":"The sacred seed-sound of the Dark Goddess…","f":"krim क्रीं krim krim kreem kriim kreen the sacred…"}
```

Generated by the endpoint `src/pages/search-index.json.js` at build time.
Measured: 965 rows, 407 KB raw, **76 KB gzipped**. Served with
`max-age=3600, stale-while-revalidate=86400` and fetched only on first focus or
keystroke — never on page load.

Behaviour: filter the visible name list as you type (no page reload), `Enter`
opens the first hit, `Escape` clears. Results highlight the matched substring.

**Full-text search of the elaborations is deliberately out of scope for v1.**
The corpus is 3.4 MB; shipping it to browsers to search prose nobody types
would cost every visitor for a query almost nobody makes. If it is added later,
it is Pagefind over `dist/`, accepting its diacritic weakness, with the folded
name index kept as the primary path.

## 5. SEO

Static HTML is the whole strategy; the rest is discipline.

**On every page**

- `<title>` ≤ 60 chars, `<meta name="description">` ≤ 158, unique per page.
- `<link rel="canonical">` — absolute, trailing slash, no query strings.
- Open Graph + Twitter card, `deity-og-1200x630.avif`.
- `robots` = `index,follow,max-image-preview:large,max-snippet:-1`.
- One `h1`; headings descend in order.
- Content — Devanagari, IAST, meaning, elaboration — present in the HTML source
  with JavaScript disabled.

**Structured data**

- `WebSite` on `/`, with `potentialAction` for the name search.
- `BreadcrumbList` on name and range pages.
- `Article` on name pages: `headline`, `about` → the name, `isPartOf` → the
  Sahasranama, `inLanguage: "sa"` for the Devanagari block.
- `FAQPage` only if a real FAQ exists. Never markup that is not on the page.

**Crawl surface**

- `@astrojs/sitemap` → `sitemap.xml`, every name page, `lastmod` from the
  content file's mtime.
- `robots.txt` allows all, points at the sitemap.
- `llms.txt` — a short hand-written summary with links to the hub and ranges.
- Internal linking: each name page links to its range, its neighbours, and every
  alternate spelling page. No orphans; the build fails if a name page has fewer
  than 3 internal links.
- `_redirects`: `www` → apex, 301. Trailing-slash canonicalisation.

**Title formula**

```
क्रीं (Krim) — Name 1 of the Kakar Adi Kali Sahasranama
```

**Description formula**

```
Krim (क्रीं, Krīṃ) is name 1 of 1,000 in the Kakar Adi Kali Sahasranama: <meaning>.
Also spelled Kreem, Kriim, Kreen.
```

not an aspiration.

## 7. Build and verify

```bash
npm install
npm run dev      # dev server with hot reload
npm run build    # parses output_names/ → dist/, 985 pages in ~4 s
npm run preview  # serves dist/
npm run check    # build + scripts/check-links.mjs
```

`npm run check` fails on: a parse error, a broken internal link, a `dist/` file
outside the allowlist, or any `private/`, `output_names/` or Markdown path that
reached the output. Verified output: 1,017 files, 36,316 internal links, 0
problems.

No browser test suite yet. Visual checks were done by hand at 390 px and
1440 px, in both themes.

---

## 8. Publishing

Output directory: `dist/`. Deployed with Cloudflare Pages **Direct Upload**,
never through Git integration. `_headers` and `_redirects` ship from `public/`;
the `www` redirect is commented out until the domain exists.

`dist/` must contain no Markdown, no `output_names/`, no `private/`, no
`AGENTS.md`, no source text. The `npm run check` guard above enforces the file
type allowlist; `_headers` and `_redirects` come from `public/`.

Publishing is a remote write under `AGENTS.md` §0 and needs the owner's explicit
approval every time.

## 9. Risks

1. **The 3.4 MB of elaboration prose.** Server-rendered per page is fine; the
   risk is a designer putting all of it in one client bundle. Never ship the
   corpus as JSON for the reader to render.
2. **Devanagari font weight.** Tiro Devanagari Sanskrit ships at 185 KB, and a
   default `pyftsubset` pass only reaches 138 KB. Subsetting to the 63 codepoints
   this corpus uses, with the Devanagari shaping features kept and hinting
   dropped, reaches **67.8 KB**. Regenerate it if the corpus ever gains new
   glyphs.
3. **Duplicate names.** 35 names repeat. Handling them by aggregation (§2) is
   mandatory; a naive one-page-per-position build ships thin duplicates.
4. **Search expectations.** The folded index finds names and their meanings, not
   prose. Label the input "Search names" so the limit is honest.
